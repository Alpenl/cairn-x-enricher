# 阅读与筛选性能

性能验收分开记录首次访问、缓存命中及请求取消。重复点击很快，不能替代首次打开文章和筛选的验收。

## 请求优先级与图片

浏览器只启动最多两个可见图片请求，列表使用 `/api/images/{key}?size=160`。等待正文时暂停图片；离开文章、移除节点或切换账号会取消无用请求并释放 Blob URL。图片仅保留在当前页面内，不进入离线存储。正文及放大查看使用原图。

NAS 生成最长边 160 像素的缩略图，以有界内存缓存派生结果。每次读取仍验证上游归属、删除状态和源图片版本；浏览器响应保持 `private, no-store`。强 ETag 的条件读取可以复用派生图，但不能跳过授权或删除检查。新 Worker 通过图片隐私能力确认省去 NAS 为旧版后端保留的两次收藏详情读取；未确认能力时继续使用旧版校验。

解码同时约束原图字节数、像素数和并发数。无法安全解码的缩略图不阻塞正文，原图接口保留独立行为。

派生图缓存最多 128 项 / 8 MiB，闲置十分钟后过期。成功的上游 304 校验只为同一缓存代次、ETag 和源内容续期；迟到的旧请求不能延长替换版本或恢复已删除的条目。

## 编辑与导航

标签连续筛选可以复用同一视图的完整摘要快照。列表每页最多 60 条；只有服务端确认有效标签、内容功能与主题粒度合同，且没有下一页、行数与总数一致时，才在浏览器计算主题、细分主题、资源类型、内容功能、自定义标签及整理状态的组合和计数。未知条件、全文搜索、来源、时间、实体和旧版维度继续由服务器查询，不从当前可见的局部列表猜测全库结果。

快照沿用精确查询缓存的十秒期限、十项和 4 MiB 上限，派生查询不会延长有效期。写前、写后、账号变更、发现内容变更及显式刷新均清理快照。直接进入带筛选条件的链接时，若 overview 确认当前视图不超过 60 条，前台列表完成后最多低优先级预取一个完整页；离开查询取消预取，失败不影响当前结果，不遍历大资料库。过期或不完整时仍回到权威查询。

侧栏计数返回时原位修改数字，仅在具体主题候选变化时更新相关分组，保留未变化的导航按钮、展开状态与键盘焦点。

折叠的标签面板使用阅读响应已有的有效标签。只有展开编辑时才读取完整来源、人工状态和建议；同一篇文章的并发刷新合并，关闭时取消无用读取。保存及冲突处理仍按版本和操作身份执行。

自定义词表在账号范围内短期复用，修改后失效，内容变化才触发词表事件。侧栏隐藏或计数组全部折叠时不发筛选计数请求；重新打开时使用当前查询。现有精确查询缓存、旧响应隔离和写后失效继续生效。

阅读面板实际不可见时暂停身份轮询，返回时重新检查；连续无变化时延长轮询间隔。后台摘要同时提供导航统计，避免成功刷新后立即重复请求 overview。后台失败列表只传摘要。

网页的摘要列表显式请求 `include_cache_identity=1`。筛选、分页及搜索返回的正文版本与来源版本均相同时，保留已读正文；版本改变或旧服务未提供有效身份时重新读取。未选择此选项的客户端保留原有列表形状，账号切换和写后失效继续清理本机缓存。

## NAS 与 Worker

新版、旧版词表都使用有界缓存和共享加载，网络等待期间不持有缓存锁。显示名修改使缓存失效，旧加载不能填回新修订；读取失败时保留明确的过期状态并短暂退避。

常规浏览器 `fetch` 保持 `cache: "no-store"`，响应也保持 `no-store`。它自动附带的 `Cache-Control: no-cache` 不再清理 NAS 应用词表缓存；显式 `refresh=1`、词表修改和 TTL 仍使缓存失效。

完整标签详情把有效选择、人工来源、源可用性和自定义标签放入同一个数据库快照。人工来源只读取计算确认/撤销所需的操作上下文，保持原有整理语义。

Worker 的数据库、策略读取和对象存储操作统一计时。SQL 数量、数据库往返和可用的读取行数分别记录；无法取得的行数元数据明确标记为未知。NAS 的共享加载有独立计时，区分缓存命中、等待同一加载和实际上游读取。并行请求的累计等待不能直接从总墙钟时间相减来推断 CPU 开销。

冷启动或过期的观测策略读取与业务读取同时开始；返回策略头、输出日志之前仍等待本次策略确认。共享读取、关闭日志、诊断过期及策略服务不可用时的行为保持不变。

## 搜索索引

Worker 迁移 `0051_search_read_model.sql` 维护有效实体和全文检索候选表。候选索引用 ASCII 大小写折叠后的 UTF-8 相邻字节，最终仍按原有逐字段子串规则校验，因此中文、标点、多个关键词及字段边界的搜索语义保持一致。缺少可用候选单元的短查询继续使用完整匹配。

索引通过同一数据库事务中的触发器跟随正文、备注、实体及人工操作更新；过期实体、人工拒绝和删除必须同步反映。索引是可重建的普通 SQLite 表，不使用影响现有 SQL 导出恢复流程的虚拟表。部署前在私有数据库副本演练回填，并比较全部原有事实表。

`0052_incremental_search_fields.sql` 增加分字段文本及候选单元引用。只重新分解发生变化的字段；全局候选与频次仅在首个引用加入、最后一个引用移除时改变。修改短备注或收藏理由不再重建整篇正文的候选索引。字段分隔、空值与 UTF-8 字节边界仍生成与原索引相同的候选集合，最终匹配方式保持不变。新增派生表占用额外存储，迁移前须核验旧索引逐值一致及导出恢复。

## 离线存储

IndexedDB 升至版本 2，文章正文和轻量容量元数据分开保存。版本 1 的有效副本在升级时迁移一次；普通读取只取目标正文，更新只写目标正文，淘汰只删除对应条目。

容量元数据与正文仍在一个事务中修改，多标签页并行写入也必须遵守最多 20 篇、8 MiB、七天过期的边界。账号隔离、写操作前后失效及旧请求不能重新写入过期副本的保护保持不变。导出全部副本时才读取全部保留正文。

## 验证

- `make verify`：Go lint、race 测试、前端检查及构建。
- `make test-browser`：真实 Chrome 交互、离线迁移和账号/修改竞态。
- `make test-image-browser`：实际代理与浏览器的图片删除、版本及缓存合同。
- 配套 Worker：`npm test`、`npm run typecheck`、`npm run deploy:dry-run`。
- 固定配对提交：`tests/local-integration/run.sh` 和 `tests/local-integration/browser-e2e.sh`，使用本地 Worker/D1/R2 与零付费模型夹具。
- 发布后以 GET 核对全部收藏的标签/阅读合同，并复测首次筛选、重复筛选、首次正文、图片字节和关键请求排队时间。生产收藏和数据库快照仅放入受限恢复目录，不上传公共测试产物。
