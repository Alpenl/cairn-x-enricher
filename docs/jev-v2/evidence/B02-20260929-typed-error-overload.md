# B02-T06 局部交付：TypeSafe 529、未知冲突与取消边界

日期：2026-09-29。TypeSafe 当前 [HTTP API 文档](https://docs.typesafe.ai/api.md) 明列 401 鉴权失败、422 请求验证失败、429 限流、529 暂时过载，并要求 429/529 使用退避。此前模型错误分类只把选定的 500/502/503/504 视为暂时故障；529 因而落入 `unknown`。无原因码的 409 则一律当作输入已过期，可能错误释放仍有效的分类租约。

## 修复与验收

- 模型与 Worker 的 500–599 均归为暂时故障，包含 529。401/403、422、429 等原分类保持；Worker 已知的 `target_changed`、`input_changed`、`lease_expired`、`already_completed` 等原因码仍优先于 HTTP 状态。
- 未知的模型或 Worker 409 归为合同错误，暂停受影响的分类组件，等待检查；只有明确的 Worker stale 原因码才能走 superseded。取消归为 stale，调用超时归为 transient。
- 分类模型返回 529 或其他暂时故障时，当前任务按 Worker 的持久任务退避报告一次，调度器立即停止本轮领取并开启单探测组件冷却；不会用剩余每轮容量连续消耗其他租约。冷却后单个半开探测成功才恢复。
- 本地 HTTP 夹具覆盖 401/422/429/529/503/409 和畸形响应；模型/Worker 错误分类测试覆盖 5xx、超时、取消、明确与未知 409。处理器测试用五条待领取任务证明首次 529 只领一条，冷却内不再领，之后一次探测恢复。所有供应商请求均为本地夹具，没有真实付费调用。
- 真实本地 Go→Worker/D1 半开集成复验覆盖 401 暂停、503/网络故障延长冷却、来源/阅读在分类暂停期间继续运行，以及两个独立客户端各一次恢复探测。测试原来只给第一个客户端登记 question spec，第二个会在领取前因能力校验失败而暂停；已补齐第二个客户端的登记，避免假通过。

`make verify`、`make test-ablation` 和最终精确提交 CI 的结果见本次 issue 交付记录。
