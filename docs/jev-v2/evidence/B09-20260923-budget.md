## 缺陷与行为变化

[上批固定快照](B10-20260923-scope.md)的原始探针在总调用上限 1 下实际调用 2 次、退出 1。原因是 Entities / RerankCandidates 每次新建账本，且 MaxCallsPerItem / Timeout 没有进入真实执行。Worker `budget_ledger` 只有表，没有通用扩展授权入口。修复前的 7 个真实 Worker HTTP/D1 场景均失败（404）：[失败日志](logs/20260923-extension-budget/budget-worker-baseline-final.log)。首次草稿使用错误环境变量名造成 auth_not_configured，纠正夹具认证后才采集这份 404 对照。

现在 `serve` 的 Worker 与 dashboard 共用 Service，独立 `classify` 命令也接入同一协议。模型和受控补材料调用前，先通过本进程的并发安全账本，再申请 Worker/D1 原子授权。范围为同一 Worker 部署、UTC 自然日；全局 20 次，每条收藏 2 次。多候选重排对每个候选计整次消耗，全局仅计一次。更新 query、换 flag、重启消费者或删除收藏都不能绕过已记入的全局每日消耗。午夜是显式固定窗口边界，不是滚动 24 小时窗口。

新增内部 `POST /api/v2/extension-budget/reserve`，只有 enricher token 可访问。现存 0011 表和 0026 删除守卫即可使用，无新增迁移。全局记录仅随机 key、计数、kind、payload hash，不含收藏 ID/原文/检索词；逐条记录在删除收藏时清理，全局不退款。D1 batch 同时检查所有候选存在、全局/逐条 call/token 上限，并同时记账。重复 key 不再次授权；异 payload 409。

65,536 输入 token / 调用按 [官方 Jev 1.13 模型上限](https://docs.typesafe.ai/models)（2026-09-23 核查）预留，输出免费。不是实际 usage，也不声称字符或候选数能准确估价。全局最大 1,310,720，逐条最大 131,072；失败和未知结果不退款。真实序列化请求仍经字节上限预检；只支持已核对上限的固定 `jev-1.13.0`，移动 alias/其他版本预调用拒绝，返回的固定模型身份也须一致。

五个新环境变量可以收紧额度或 20 秒 deadline，不能扩大 Worker 上限；详见 [配置与运维](../09-semantic-extensions.md)。调用者取消、超时、旧 Worker 404、401、503、截断/非法确认和耗尽均不增加网络重试；模型扩展失败保留原分类，重排回当前候选原序。授权已提交但响应丢失会浪费额度、不会发模型请求；这是明确的保守取舍。
