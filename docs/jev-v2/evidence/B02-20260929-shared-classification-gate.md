# B02-T07 局部交付：跨进程分类供应商门闩

日期：2026-09-29。此前 TypeSafe 429/529 的 `Retry-After` 已进入**当前任务**的 D1 `next_retry_at`，但另一进程仍能领取另一条分类任务并调用同一供应商。本次把分类供应商冷却期移到 Worker/D1，并在真正付费的预算预留处再守一次门闩。

## 合同与状态

- 0046 迁移增加独立的 source、reading、classification 门闩行和任务领取时的组件代次。现在只接入 classification；来源和阅读不受 TypeSafe 门闩影响。
- 首次 429/529 或暂时性传输故障由 Go 在当前任务失败报告中标出。Worker 在**同一 D1 batch 事务**中写入任务退避与组件 open 状态。组件退避从 30 秒翻倍至最多 10 分钟，并取有上限的供应商提示较晚值；同一代次的并发旧失败不能重复延长故障。任务原有 5 次尝试和按日付费预算未放宽。
- 退避到期且有满足原有快照、租约和预算条件的候选时，领取与 probe 所有权在同一事务完成；空队列不清除故障，也不取得 probe。probe 持有者独占最多 5 分钟，进程退出后下一处理器可接手。只有持有该 token/代次的成功分类提交能在同一事务内关门；旧在途任务的成功不能清除新故障。probe 失败延长退避。
- TypeSafe 每次付费请求前的 Worker 预算预留再次检查门闩。门闩 open 时，旧租约拿不到新付费许可；probe 只能使用自己的租约。门闩使 Worker 的分类领取返回带 `Retry-After` 的 `component_paused`，Go 在本地缓存这个期限，避免每轮重复握手与读库。
- 新 Go 领取请求声明 `X-Cairn-Classification-Gate: 1` 后才收到 `component_epoch`/`component_probe`。旧 Go 的严格 JSON 解码收到原响应形状；它仍可在退避到期后接手**一个** probe，成功提交关门，失败报告由 Worker 标记为 `probe_failed` 并延长退避。新 Worker 先于新 Go 发布。旧 Worker 不理解 0046 门闩，因此回滚 Worker 前必须先停掉分类领取，并在恢复到兼容 Worker 后核对持久门闩与付费账本。
- 门闩 `opened`、`probe_started`、`closed` 只在 D1 提交成功后进入现有 off/basic/diagnostic 日志热开关；固定事件不含收藏 ID、租约、原文、请求或供应商正文。D1 门闩和预算账本仍是事实依据，日志丢失不能当成成功或失败。

## 本地验收

- Worker 真实本地 D1 测试：历史 0045→0046 迁移保留处理中的任务；三条候选并发只领取一条 probe；另一个任务尝试次数仍为 0；空队列不清故障；旧在途成功不关门；probe 进程退出后可接手，失败延长退避；旧协议响应无新字段且可恢复；预算预留在门闩 open 时不记账，probe 所有者可记账；source 领取不受阻。日志测试核对三种固定转移、热开关及无敏感字段。
- Go 单测覆盖共享 `Retry-After` 在本地缓存以停止重复 Worker 轮询。真实本地 Go→Worker/D1 使用 TypeSafe 529/8 分钟夹具：第一个任务只调用模型一次，新建 Go 处理器面对第二个已就绪任务收到组件暂停，第二任务 attempt 保持 0。另一个本地 Go→Worker/D1 用例复核 401、503、网络故障、半开恢复，以及分类暂停时来源/阅读仍可完成。
- 完整 `make verify`、`make test-ablation`、Worker 全量 Vitest、TypeScript 类型检查、Wrangler dry-run 均通过；本机 `npm` 缺少 `semver`，Worker 使用仓库内的 Vitest/TypeScript 可执行文件跑同一脚本内容。精确提交 CI 与迁移回滚/性能数据在 issue 交付记录中补充。
