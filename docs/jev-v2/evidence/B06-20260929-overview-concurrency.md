# B06 / P2–F3：导航聚合并发与整理反馈（2026-09-29）

## 行为

- Go 的 overview 与 backstage 共享有界的单次计算：缓存锁只保护快照和在途记录，上游 HTTP 在锁外执行。同一失效代次的并发请求共用结果；本地整理使代次增加，新请求不会加入旧计算，旧计算也不能回填缓存。计算由服务上下文管理，最多 20 秒；单个浏览器断开不取消其他浏览器共用的读取。backstage 的失败/耗尽列表并行读取。
- 刷新失败时返回上一份有效快照，响应带 `stale: true` 和 `Warning: 110`；无旧快照仍返回错误。失败后 1 秒内复用旧值，防止上游故障时每个轮询都再次请求。
- Web 整理状态改变时立即更新导航视图计数，处理成功与失败分别保留或回滚；待确认计数遵循 Worker 的 `curation IS NULL` 条件。连续整理完成后 5 秒尾随刷新 overview，在途旧响应不能覆盖乐观计数。`/status` 在启动、可见页面的 30 秒周期和从隐藏恢复时检查，不随每次整理请求。
- 浏览器夹具把 `classification_reviewed` 与 Worker 的 `curation IS NOT NULL` 映射对齐。显式把状态改回收件箱后，该条仍不算未整理的“待确认”。

## 验证

- `make verify` 通过：完整 Go race 测试、lint、vet、构建和 488/488 前端检查。Chrome 128/128 检查通过；整理后导航计数先变化，900 毫秒内没有追加 overview 或 `/status` 请求，撤销恢复收件箱计数并保持待确认计数的有效语义。
