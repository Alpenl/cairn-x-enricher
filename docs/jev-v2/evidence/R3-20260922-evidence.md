## Implemented behavior

- The atomic v2 claim requires a snapshot at the current content revision, a nonempty completeness state, and a primary block matching the current source. ID/hash/revision come from that same row. Pending checkpoints do not consume classification attempts. Legacy unbound jobs keep their explicit plain-text compatibility path.
- New additive migration `0017_source_context_revision.sql` advances content identity for context-only source changes; primary/URL changes remain covered by 0014. Existing rows are retained and there is no backfill. Older application versions can still read the schema; rollback keeps the additive trigger and historical data. Production migration was not run.
- Identical objective bytes can be checkpointed at a newer source revision; the old immutable row is retained rather than reused under the wrong revision.
- Reading retries inspect the current checkpoint and repair a missing/stale one from the saved source without another retrieval. An existing current snapshot is preserved, including extension blocks.
- The processor reads bound evidence within its classification deadline, validates snapshot ID/revision/hash, and checks SHA-256 of the canonical objective snapshot payload returned by the Worker. Bad reads, bad identity and altered bytes cannot fall back to plain text. Empty/duplicate blocks, invalid roles and ambiguous primaries are rejected before inference.
