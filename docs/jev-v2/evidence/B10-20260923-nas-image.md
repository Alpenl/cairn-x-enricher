## 旧实现的实际失败

[HTTP/组件失败对照](logs/20260923-nas-image/nas-image-baseline.log)在旧生产代码上运行新回归，记录：

- 缺缓存头时代理补上一周 immutable；上游 public/immutable 或 private/max-age 被原样传给浏览器。上游单独 no-store 的旧行为本已禁止缓存；该分支失败只来自新断言要求额外 private，不能冒充隐私泄漏证据。
- 收藏检查应返回 404、401、503 或错误 ID 时，旧 GetImage 根本未读详情，仍返回图片。live 分支的失败只证明缺少两个详情检查，不代表原来正常图片不可读。
- 测试使用实际 Go HTTP 客户端/代理与旧合同 HTTP 夹具，后端主动继续提供孤儿对象，非声称已部署的旧 Worker 曾被本批运行。

## 最终实现

- `GetImage` 验证 key/正整数所属 ID，取图之前和取得响应后各读一次详情；`GetBookmark` 必须返回请求 ID。不存在、未授权、故障或错误身份均拒绝，后验失败关闭已取得的图片流。保留 typed API 错误，使 NAS 正确返回对应错误；不把失败当确认，也不进行模型调用。
- NAS 成功图片响应统一 `private, no-store`；错误响应沿用统一 no-store。去掉从后端透传 Cache-Control 以及一周 immutable 默认。保留内容类型、长度、ETag、Last-Modified 和原有截断检测。
- `CairnUI.imagePath` 增加稳定 `?privacy=1`，迁移旧浏览器缓存键。图片名按来源 URL 哈希，不是 bytes 的内容地址，同 key 内容可以更新。
- 每次成功取图增加两次未缓存详情 HTTP 请求，换取旧后端兼容下的删除检查。后端失败时拒绝图片，可能降低故障期间可用性。没有新增外部模型/来源调用。

## 边界与后续

新响应 no-store 不会远程擦除旧页面、导出文件或用户手动使用的旧缓存 URL；最终存在性检查之后已开始发送的 bytes 不能撤回。旧 Worker 的物理孤儿清理仍依赖配套服务端修复/迁移，NAS 不代替它清 R2。没有承诺全保留期或固定擦除 SLA。依据 [RFC 9111 §5.2.2.5](https://www.rfc-editor.org/rfc/rfc9111.html#section-5.2.2.5)，新响应禁止存储不等于撤回既有副本。
