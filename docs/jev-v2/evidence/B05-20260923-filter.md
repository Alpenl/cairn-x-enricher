## 改变后的真实行为

两个实际列表入口 `/api/links` 与 `/api/enrichment/jobs` 共用参数化筛选。第四主题不再被旧三主题投影截掉，功能/载体/用途和实体状态不再静默忽略。未知、空分项、同名重复与超界参数返回 400。稳定 ID、同维 OR/跨维 AND、旧单值参数和已知停用 ID 的历史可查语义见 [固定合同](../05-taxonomy-api.md)。旧返回字段/type 不变；只有选择新参数才采用对应查询条件。

有效标签从最新决定、原始 legacy 层和 revision/id 有序人工动作推导。SQL 与 canonical fold 对照，覆盖历史别名、明确清空、逐标签恢复、整维恢复、单值 A→B→A 及选中值拒绝后不复活旧接受值。mutable projection 不是输入，没有先截取候选再过滤。实体状态独立核对内容版本和实际 snapshot/hash，人工实体纠正不会冒充自动成功。

计数采用相同语义条件，保留各任务状态供页签切换，不随 status 页签/limit/before_id 缩小。列表与计数在同一 D1 batch 事务读取；该事务语义依据 [Cloudflare D1 文档](https://developers.cloudflare.com/d1/worker-api/d1-database/#batch)。App 缓存键纳入所有新条件并提升缓存版本。迁移 0025 对 content revision 变化及 evidence snapshot 新增建立事务内失效，避免详情已经 stale、缓存列表仍 completed_nonempty；不修改人工记录、决定或正文。
