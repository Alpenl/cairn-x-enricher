## 原行为与生产路径

旧实体生产 Service 只有 Noul 实质相关判断和去重后的名称列表，`EntityVerdict` 辅助类型没有进入实际请求与存储。相同名称在不同来源的出现被提前合并，无法保存两个受控身份及第三处未知。相同黑盒用例对旧 E `57e1e5f` / S `0ae27c8` 编译真实 CLI 后，在已完成的实体结果读取处失败：有 `entities:["Acme"]`，却没有三处身份记录：[旧实现对照](logs/20260923-canonical/canonical-baseline.log)。不是因新 Go 类型缺失而编译失败；测试使用本地 DTO，临时覆盖文件随后清理。

现在 `serve` / `once` / `classify` 的真实 Service 使用新的发生位置候选与 Choice 流程：每处记录 block ID、原文表面名和精确 rune 区间，重复名称按位置分别保留；旧 UI 名称列表可以去重，但不据此合并 canonical 身份。只从存档文本与已有来源链接取候选，不让 Jev 造名称或重新 X Search。最多 40 处；超过既有实体字段 120 UTF-16 单元的长片段跳过，不截断造名。该解析器仍有候选覆盖局限，不宣称实体召回已达标。

相关性 Choice 明确区分 relevant / incidental / none / unknown。存在受控身份选项时，在同一个模型请求独立询问 canonical 匹配，选项只含有限 ID、none、unknown；问题明确不能读取另一题答案或只按同名推断。完整分布和 confidence 按现有 typed 概率合同验证，缺题、多题、越界值、非法概率/总和、置信度异常均拒绝。代码仍使用临时 0.8 接受阈值；低于阈值保留 unknown。新的 Choice 语义未据本批夹具做质量校准，不能把旧 Noul 阈值经验当作新质量证明。接口形状与有限选项的依据见 [TypeSafe Choice](https://docs.typesafe.ai/primitives/choice)、[预解析候选选择](https://docs.typesafe.ai/cookbooks/pre_parsed_value_extraction_cookbook)及 [HTTP API](https://docs.typesafe.ai/api)（2026-09-23 官方 HTTPS 原文核对）。

## 受控目录和身份依据

运营者通过 `CAIRN_ENTITY_CATALOG_PATH` 指定本地 JSON，启动时读取；路径和目录不能由收藏正文或模型答案决定。未配置时相关性继续执行，受控身份为 unknown；实体关闭时不读取目录，普通分类不因目录缺失受阻。目录调整后重启消费者，不自动回填历史。

目录含 version、稳定 ID、label、kind、aliases、identifiers；支持人物/组织/产品/项目/地点。最多 1 MiB / 200 个实体 / 每项 16 别名、8 身份 URL。重复 ID、跨实体冲突 URL、非 HTTP(S)/带凭据 URL、未知字段、额外 JSON 和非法大小在启动时拒绝。文件通过其父目录的 `os.Root` 有界读取；不是开放的网络文件下载。完整格式及限制见[运行说明](../09-semantic-extensions.md#有限实体身份与逐处来源0030代码准备)。

每处最多 8 个身份选项，只保留名称/别名匹配且身份 URL 出现在**该来源块**的候选；块 URL、块正文精确 URL 和已存链接分别记录依据类型。另一个块的同名或 URL 不能给本处授予身份；身份过多时整组 unknown，不截断后误选。URL 仅比较，不执行抓取。Worker 再次核对来源位置、实际快照、受控定义的一致性及 URL 归属；集合外名称/ID、伪造区间/来源、矛盾目录定义被拒绝。身份 URL 存在仍不等于真实同一实体：Jev 需判断其与该出现的关系，真实误合并率留给自动参考质量评估。

## 持久化、复用与人工优先

生产缓存请求 `entity_protocol=2`，含实际序列化材料、完整候选、有限目录选项与版本、问题/策略身份。缓存保留完整 Choice raw，命中不推断；目录内容/版本、问题、候选或策略变化不命中旧 key。原 Noul 缓存协议仍可读取历史，新消费者遇旧 Worker 的不支持合同会在 claim 阶段拒绝，不回退重复付费。仍使用固定 `jev-1.13.0`、原持久预算、真实请求字节上限、唯一执行权及丢响应恢复，无新增收费旁路。

0030 给 entity_states 增加 `observations`；旧记录为 []，不补造 provenance。每条 observation 保存原文位置、明确相关性、有限身份定义、目录版本、原始 Choice、选中 ID/label/kind 以及独立身份 URL 依据；同名的不同身份并列保存。状态/操作记录与输入 snapshot ID/hash/revision 同事务绑定，原始输入仍由不可变 EvidenceSnapshot 指明。Worker 根据 raw 重算选择结果，拒绝伪造展示字段。短期缓存删除后这些记录仍在；本批不把这个范围扩大为所有历史、模型题目或 usage 的无限期保留承诺。

API 增加 observations（归档判断）与 effective_observations（当前、实质相关且在人工有效集合内的记录）。人工 reject/reset 保持既有表面名级语义，拒绝后当前有效记录为空，重置恢复；来源变更后旧记录仍可查看但不再是当前结果。失败/not_run 不清除同输入成功；旧消费者无逐项来源的同输入结果也不能覆盖已保存的逐项成功。删除收藏清除 state 与操作记录。completed_empty 表示接受的实体集合为空，内部仍分别保存 none / unknown / incidental，不把未知判断伪造为确定不存在。

Web 新增“自动判断依据（人工整理优先）”，区分原文、受控名称/类型、身份链接、来源区间和非当前有效结果，文本使用 DOM textContent，不执行来源指令。实际浏览器验证人工拒绝后阅读头部/导出清除名称，依据保留并标记历史，reset 恢复。
