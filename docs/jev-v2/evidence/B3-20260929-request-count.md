# B3 请求数回归基线（2026-09-29）

本报告是 [性能 issue #20 的 B3](https://github.com/Alpenl/cairn-x-enricher/issues/20) 局部证据。测试使用 Enricher `13d9846`、Share `3948e17` 为改动前基点；本报告对应的测试代码随同一 PR 提交。所有供应商行为由本地夹具模拟，没有付费网络请求。

## 一条新收藏：真实 Worker/D1↔Go 路径

`CAIRN_INTEGRATION_CASE=sourcelease bash tests/local-integration/run.sh` 启动本地 Wrangler/D1，再由真实 Go `processor.Process` 完成一条无图片收藏。HTTP transport 逐次记录该处理段到 Worker 的请求（不计建收藏、能力握手、领取和最后验收读取）：

| 阶段 | Worker HTTP 请求 | 次数 |
| --- | --- | ---: |
| 来源检查与写入 | `GET source`、`GET job`、`POST source`、`POST evidence` | 4 |
| 阅读前状态检查与完成 | `GET job`、`POST complete` | 2 |
| 两个付费阶段的租约准入 | `POST lease-admit` | 2 |
| 两个付费阶段的尝试账本 | `POST reserve`、`POST settle` | 4 |
| **合计** | | **12** |

测试现在要求该夹具的处理段最多 12 次，并要求两次租约准入、两次预留和两次结算确实发生。同一个本地联调还模拟来源供应商结果不明：处理段为 5 次 Worker HTTP 请求（来源检查、job 读取、租约准入、一次预留、失败写入），要求最多 5 次、无结算，且失败收藏保留 `paid_call_unresolved`；随后领取不到第二次执行许可。原审计中的“最多 7 次”来自加入租约准入与逐网络尝试账本之前的原型，不能直接用于现有安全合同。12 和 5 是两个夹具的当前上限，不是生产 p95，也不是图片、响应丢失、其他重试、分类或人工任务的通用目标；这些场景仍须按第 0 组同负载测量并单独设预算。

## 浏览器 J 导航

真实 Chrome 加载 96 条合成收藏的旧接口夹具后，按一次 J 并等相邻预取触发，新增 3 个 API 请求：下一条的 detail 预取，以及当前所选条目的 v2-selection 和 entities；当前条目的 detail 已由前一次预取取得。没有列表、overview 或 status 请求。回归测试把旧接口兼容路径限定为最多 3 次。统一阅读接口的独立浏览器场景验证：打开一条收藏时，`GET /reading` 一次提供正文、选择和实体，旧的三个接口均没有被调用；此场景还验证了仅个人修订变化时省略正文的刷新。

旧接口的 3 次不是统一阅读接口下的 J 导航目标。统一阅读接口的 J 连续操作、图片请求、快慢停留、后台刷新及多客户端失效，仍需按同一浏览器负载补全请求数和延迟证据。

## 验证

- 上述真实 Worker/D1↔Go 测试通过：成功处理段记录 12 次，结果不明的失败处理段记录 5 次；`localSourceReader` 的来源读取和阅读各执行一次，失败读取也只执行一次。
- Chrome 浏览器测试 131/131 通过，其中旧接口 J 的请求上限和统一阅读单请求均通过。
- 本报告不代表 #20 的完整性能验收；同负载的 p50/p95/p99、SQL 读写、Worker 内存和日志开销仍需第 0 组测量。
