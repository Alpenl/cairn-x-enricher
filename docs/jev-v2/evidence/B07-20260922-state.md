## 实现与兼容边界

- Go `AutomaticFromProposals` 保存版本 1 的 assessment：每个候选的 accepted/rejected/abstained、原因、概率、Choice 胜出候选及 incomplete。概率 0 不再因 omitempty 丢失。既有分类与纯策略重放共用入口；按确定顺序保存判定，避免 map 遍历顺序改变同一逻辑请求的身份。模型问题、阈值和分类选择未因此变更，未调用模型补历史记录。
- Worker 的生产完成和策略重放两条入口验证并保留 assessment，纳入原不可变 payload identity。现有 JSON 列即可保存，无新数据库迁移。旧消费者没有该元数据时仍可提交；旧决定没有元数据时显示 unknown，不能由空数组反推“已完成空结果”。Choice 记录是实际胜出候选及策略结论，不宣称提供完整备选分布。
- `GET /api/bookmarks/:id/v2-selection?include_automatic=1&include_state=1` 显式协商新状态。默认响应 shape 不变；旧严格 Go 读者通过真实集成复验。新 App 对不含 state 的旧后端保留值并显示未知。未新增管理权限、付费动作或默认后台任务。
- 一条 SQLite SELECT 同时读取链接版本、最新决定、该决定引用的运行覆盖率、按 revision/id 排序的人工事件、legacy 捕获层、当前证据和独立实体状态。既有 `computeEffective` 也使用该快照，避免把个人版本 N+1 标在 N 的值上；不把 query projection 当真值。当前 source 完整不等于模型输入完整，读取所引用运行的 evidence_coverage 识别预算裁剪；运行回答 partial 单独标记。
- 每字段/标签来源沿现有 override fold 推导。accept、reject、set_empty、reset 会相应更新或移除来源；历史 legacy_unknown 保持未确认，why/status 不被当作接受行为。自动运行状态和人工有效值分开：人工明确留空不会改写自动判断。实体独立验证自己的 snapshot/content revision/hash，分类尚未运行也能有实体结果，失败/过期的自动实体不进入有效值。
- Android 校验选择本体与非负整数 revision；缺失/畸形选择返回失败。未知 state 版本、版本不匹配、来源值与有效选择不匹配时放弃状态元数据，不冒充人工确认。本地待同步字段单独标记，界面和导出都不沿用已保存来源来声称草稿已确认。
- 界面显示六维状态、来源、可展开的保存判定、独立实体状态、partial。主题摘要只折叠显示，全部值仍保留；编辑 chips 使用 FlowRow。导出保留全部有效标签、每项来源、why、状态、部分证据及独立实体，不再从旧 classification.entities 取当前实体。载体保持单值，潜在用途不等同实际收藏意图。

判定和概率的语义依照项目 TypeSafe skill 及当日读取的 [API](https://docs.typesafe.ai/api) / [Confidence](https://docs.typesafe.ai/confidence)：概率用于保存模型判断，不当作实测准确率或人工 gold。Web 工具读取最初失败，随后通过 curl 成功读取当前 Markdown 文档。
