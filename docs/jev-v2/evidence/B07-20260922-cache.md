## 可选缓存协议与迁移

Android list/detail/update 显式请求 `include=enrichment&include_cache_identity=1`。默认响应字段保持不变，旧严格 Go 读者不受新增字段影响。缓存键区分是否协商；已热的旧 summary/detail 缓存不污染新响应。

`enrichment.cache_identity` schema 1 包含 `representation`（summary/detail）、`content_revision`、`body_revision`、`personal_revision`、`latest_decision_id`、`latest_entity_revision`。最后两个是同一次 SQL 读取时的最新规范状态失效标记，**不是 legacy classification 投影的来源证明**；来源 DTO 仍见剩余任务。

迁移 `0023_app_body_cache_revision.sql` 为省略在 summary 中的 original_text/translated_text/related_links/images 增加实际变化版本。相同源正文、相同时间戳的译文或附件变化仍使详情缓存失效；相同内容重写不加版本。旧行从 0 开始，本协议尚未存在的历史缓存无此身份，混用时不复用。App PATCH 在 SQLite AFTER triggers 执行后重新同时读取正文和身份，避免 RETURNING 带回旧版本。

Android 只在已知 schema/representation、content 与 body 两个版本相同，并满足 URL/备注/状态/时间等已有约束时保留旧正文。未知或畸形身份不复用；老服务只有双方都不含身份且非空相同时间戳时走兼容路径。列表仍不传两份大正文。本批仅本地迁移，未执行生产迁移或部署。
