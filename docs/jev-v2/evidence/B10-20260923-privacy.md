## 旧行为与修复

原 B10 的 “every private v2 table” 测试直接执行 SQL 删除，只检查六张表且部分没有填数据；它不证明 HTTP 删除、R2 或最新关联表完整清理。本批新增独立、已填充的验收，保留原回归和历史报告。

[旧实现失败对照](logs/20260923-privacy/privacy-baseline.log)在未改生产源码时复现三条：HTTP 删除后两个 R2 对象仍存在；删除后孤儿图片条件请求仍返回 304；put 在删除后完成仍返回 200、遗留对象。预算账本没有外键/删除清理是源码审计发现，另由已填充夹具验证修复；不把前一断言中止的日志声称为账本的独立旧失败。

- 新迁移 **0026**：删除 `links` 的同一 D1 事务中写最小删除凭据、删除关联 budget、递增 cache generation；其余内容沿既有外键级联。升级清理已有孤儿 budget，禁止未来插入/改写成孤儿的非空 link_id；全局 aggregate budget 保留。
- HTTP 删除后按 `enrichment/<id>/` 精确前缀清理全部历史对象及 metadata，不仅清 `links.images`。每请求最多 4 页×100 个；R2 故障或未清完返回 **503 / deletion_cleanup_pending / Retry-After: 300**，D1 已删除，凭据保留、重试继续。清完或已知成功重试 204；从未存在且无凭据 ID 仍 JSON 404。
- 上传 put 后重新核对收藏及租约；删除竞争拒绝完成，并清理迟到对象。图片读取在 R2 I/O 前后检查收藏存在，条件 304 也执行，拒绝/304 时释放 body。应用 token 与内部 enrich token 权限继续隔离。
- Cron 配置为每 5 分钟：一次最多处理 20 个到期删除凭据，另扫 100 个对象的一页以发现旧版本遗留孤儿，持久化 cursor 并循环。失败/分页未完 5 分钟再到期，成功凭据 24 小时复查以发现 isolate 中断后的迟到 put。存储故障、积压、定时触发延迟会延后物理清理，不宣称固定 SLA。活跃 ID 与其他前缀保持；发现的历史孤儿数字 ID 后来成为新收藏也不会误删。
- 删除凭据只保留数字 ID/时间，无原文、URL、图片、答案或 curation。它不随父项级联，确保中断后恢复义务不丢。共享 question/spec/taxonomy 定义不因一个收藏删除。
- 对客户端统一 **private, no-store**，不再暴露服务端内部的 public cache header；内部 generation-keyed Cache API 仍 15 秒过期，删除同事务使旧 generation 不可命中。此前已经下载的文件、旧浏览器缓存和客户端离线数据库不由此 API 远程擦除；客户端缓存清理与 live history 年龄保留策略仍单列待验收。

实现和不执行的部署/恢复说明：[Share privacy-deletion.md](https://github.com/Alpenl/cairn-share/blob/7b0aa9bbaad898a80ef567023e63b4f68009a252/docs/privacy-deletion.md)。先迁移后 Worker；回滚不删除新表，旧图片服务没有新存在性守卫，不能声称同等隐私保证。
