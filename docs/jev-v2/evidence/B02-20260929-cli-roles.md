# B02-T09 命令职责与组件暂停（2026-09-29）

## 实际合同

- `classify` 使用分类角色配置和 Jev/Worker 客户端；没有 Grok key 时仍可处理已保存的来源，不运行 Grok canary，也不抓取来源。
- `once` 先向 Worker 做只读来源可领取预查。来源不可领取时只跑分类/证据恢复，Grok key 和 canary 都不需要；来源可领取或预查失败时，使用完整配置并在来源领取前运行 canary。空预查后本轮不领取新到的来源。
- `serve` 始终启用来源和分类，因此必须有两组配置；即使来源队列为空，也在启动时运行 Grok canary。命令构造、root/help 和普通单元检查不访问付费供应商。
- 分类组件因 401 等配置错误暂停时，来源/阅读轮次仍可处理任务；退避内不重复领取分类任务，到期只允许有界探测，成功后恢复。

## 重复方式与结果

在迁移后的真实本地 Worker/D1、编译后的 Go CLI 和本地 HTTP 供应商夹具下运行，未连接真实付费 endpoint：

```sh
CAIRN_SHARE_ROOT=/path/to/cairn-share CAIRN_INTEGRATION_CASE=onceempty bash tests/local-integration/run.sh
CAIRN_SHARE_ROOT=/path/to/cairn-share CAIRN_INTEGRATION_CASE=cli bash tests/local-integration/run.sh
CAIRN_SHARE_ROOT=/path/to/cairn-share CAIRN_INTEGRATION_CASE=halfopen bash tests/local-integration/run.sh
make verify
make test-ablation
```

`onceempty` 通过：空队列 `serve` 缺 Grok key 拒绝启动；配置齐全时合成 422 canary 被调用一次并拒绝启动。相同空队列下，`once` 没有 Grok key 仍成功且 Grok 请求数为 0；保存来源后的分类 run 成功，Grok 仍为 0。有待领来源时，缺 key 失败，422 canary 在租约前停止，收藏保持 `pending`、尝试次数为 0。

`cli` 通过：编译后的 `classify` 在只有 Worker/Jev 配置的环境处理两条保存来源；空轮次没有额外模型调用，显式 `--id` 重试成功，原文和人工决定未变，全程没有来源抓取或 Grok 请求。

`halfopen` 通过：分类领取处的合成 401 使组件暂停，退避内不再次领取或调用 Jev；这段时间另一条来源的抓取和阅读正常完成。到期的 503/网络故障探测重新退避，后续成功探测恢复分类，每个处理器仅有一次有界恢复调用。两次 Jev 调用均指向本地夹具。

`make verify` 包括配置角色单测、root/help 零调用检查、race/静态检查、488 项前端检查和编译；`make test-ablation` 通过。Worker 的 `source-claimable` 使用与实际来源领取相同的候选 SQL；本地 2,000 条合成数据空/非空读取均小于 20 行。没有部署、远端迁移或真实付费调用。
