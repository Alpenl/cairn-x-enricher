# B06/F1–F2：阅读请求与版本缓存的局部交付

日期：2026-09-29。关联 [Enricher #13](https://github.com/Alpenl/cairn-x-enricher/issues/13)、[性能 #20](https://github.com/Alpenl/cairn-x-enricher/issues/20) 与 [Share #30](https://github.com/Alpenl/cairn-share/issues/30)。实现位于 Draft PR #17，Worker 的轻量身份入口位于 Draft PR #32。

- 邻近收藏预取与用户打开共用同一在途详情请求；已完成的预取最多保留 4 条、估算 2 MiB、15 秒。显式刷新和本端写入使旧预取失效，慢响应不能回填旧正文。
- Go 看板新增只返回版本与处理状态的 `/api/bookmarks/:id/identity`，由 Worker 单条小查询提供。可见详情每 15 秒校验身份；隐藏页暂停。版本或状态变化才重新取全文，且刷新不覆盖正在保存的原因或排队中的字段级整理。诊断面板仍独立轮询分类状态，并在分类离开 pending/processing 时刷新该条。
- v2 选择与实体读取以内容、正文、个人整理、决定和实体版本组成缓存键；列表摘要和详情的表示差异不改变键。两种结果合计最多 64 条、估算 2 MiB。本端写入清除该收藏的预取和辅助缓存；请求代次阻止旧选择/实体响应覆盖新状态。正文预取和辅助缓存分别可计量条目数与估算字节数。

Go `make verify`（含 476/476 前端检查）、真实本地 Worker/D1 的 `manualrestart`、Chrome 119/119 浏览器检查和 Worker 352/352 测试覆盖这一批路径。浏览器用受控时钟证实：空闲可见详情发现跨客户端版本变化后只多取一次全文；版本不变时不取全文；远端更新不覆盖正在保存的本地原因。前端检查还覆盖预取/打开只发一次、旧预取晚到、本端写入后重新读取、辅助缓存上限、本地编辑不污染缓存快照及强制刷新后旧辅助响应不能回填。测试均使用本地服务，没有生产性能数据或付费调用。

仍需 S2 单快照聚合接口、完整的 8 小时缓存/内存证据和 #20 同负载请求/数据库测量；这些未完成前不勾选 F2/S2/B06 最终验收。
