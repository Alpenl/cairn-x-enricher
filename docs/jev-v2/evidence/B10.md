- **B06-T06 独立状态**：`GET /api/bookmarks/{id}/classification-status` 代理，UI 分开展示 pending/processing/failed/exhausted/waiting_source 与原因。
- **B06-T07 三动作**：只重试分类（0 模型调用）、按当前策略重算（0 调用，dry-run 后显式写回）、重新抓取原文（有确认与成本说明），三者走不同后端行为。
- **B06-T09/B05-T13 导出**：`GET /api/export` 服务端 Markdown，含全部有效 v2 维度、why/来源、人工来源、过期/部分计数；首页按钮优先使用该端点，旧后端回退本地导出。
- **B09-T04 实体生命周期**：`internal/extension/service.go` 候选抽取 + 单次批量判断 + 预算 + 越界答案拒绝；状态 not_run/failed/completed_empty/completed_nonempty/stale；Worker `entity-state` 端点在事务守卫下写入，失败不清除同 revision 成功值。
- **B09-T05/T06 补证据**：processor 在分类成功后检测真实缺口（外链未取得/截断），创建 Worker evidence request（dedupe/预算），用受控 fetcher（allowlist + DNS/IP + 逐跳 redirect + MIME/大小/超时）抓取，成功则追加 external block、提交新快照并重新入分类队列；失败/被策略阻止时保留旧内容并记录明确状态。
- **B09-T09/T10 重排**：`POST /api/rerank` 只对已授权/已过滤候选做同 rubric 打分，预算/失败回原序，关闭或错误时明确 `applied:false`。
- **B09-T11/T12 提案**：Worker 从重复人工实体纠正生成 pending 提案；审批后 display-only 改名可应用（不改语义、不重评），语义变更显式返回 `requires_new_version`，不自动改词表。
