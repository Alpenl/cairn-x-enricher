## 修复的实际问题

原 DialGuard 先解析域名、检查所得 IP，再调用 `net.Dialer.DialContext` 连接原域名。连接器可再次解析域名，因此被检查的地址与实际连接地址可能不同。现在生产路径只解析一次，验证完整结果后，连接明确的数字 IP；一次解析中混入拒绝地址时，在任何套接字连接前整体拒绝。失败只能尝试同一已检查集合中的后备地址，IPv4/IPv6 限制仍遵守。

DNS 与所有连接尝试共享一个总 deadline，后备地址分配剩余时间，首个不可达地址不能独占所有预算。取消和错误保持可检查；不重新解析、不在失败时退回域名连接。HTTP URL 不改写，因此原 Host、TLS SNI 与证书主机校验继续有效。每跳 HTTP 重定向沿用原 allowlist 校验，新连接重新执行受控解析。

同时修复特殊地址漏拦：Go 的 private/loopback 等基础判断不足以识别共享地址空间、文档/基准测试/保留地址。新增显式前缀拒绝，IPv4-mapped IPv6 先归一化再判定，limited broadcast 也拒绝。登记依据为 [IANA IPv4 特殊地址表](https://www.iana.org/assignments/iana-ipv4-special-registry/iana-ipv4-special-registry.xhtml) 与 [IANA IPv6 特殊地址表](https://www.iana.org/assignments/iana-ipv6-special-registry/iana-ipv6-special-registry.xhtml)，2026-09-22 核对，两表标注更新日 2025-10-09。

这是保守的普通外链 HTTP 策略，额外拒绝协议专用网段与 NAT64/6to4 转换前缀，即使某些细分地址标记全局可达。允许名单域名解析到这些地址会返回 blocked；未自动允许特殊转换网络。策略不声称等同于完整 IANA 路由分类，也不替代主机网络出口控制。现有默认关闭 flag、源材料保存、内容大小/MIME/重定向次数、执行预算与 owner/checkpoint 协议继续有效。
