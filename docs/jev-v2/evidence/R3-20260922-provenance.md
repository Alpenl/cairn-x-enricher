## Behavior

Additive migration 0018 introduces private `legacy_curation_history` and a `curation_projection_epoch` marker. Migration captures old column bytes before any new projection write. Ordinary projection rebuilds increment the marker in the same guarded UPDATE and cannot generate legacy source records. A direct old-application write is captured by a trigger at the next personal revision. Historical input is read from the captured history, never reinterpreted from the mutable `links.curation` cache.

Captured legacy full selections clear and then set only topics/form/use, including explicit empty values; hidden content-functions/carriers/affordances remain independent. Null from an old writer is a reset. Later field-level overrides and old writes participate in revision ordering. History remains intact when reset removes active review state. Go/Worker now compute reviewed from active intent rather than merely the existence of past actions.

The v1 AI column follows the latest automatic decision, while its separate human projection is present only for active overrides. Thus four AI topics do not turn into a three-topic human confirmation, and a later automatic topic removal reaches old detail/list filters as well as the effective view.

## Existing ambiguous data

- Pre-migration curation on a row with an existing v2 current projection is archived as `ambiguous_projection`; it is not imported again as human input. Original bytes are retained. Such a cache alone no longer supplies a human override, so a row with no explicit override may display its AI baseline after rebuilding. This is an explicit compatibility behavior, not a claim to have recovered historical user intent.
- Existing override/event rows are retained unchanged. In particular, old `legacy:*`, revision-0, unconfirmed rows may have been generated by the former importer or may preserve genuine old user choices. This migration does **not** delete or automatically certify them. They remain unknown-source history and cannot be used as reliable quality labels.
- An audit can identify candidates using `legacy_curation_history.provenance='ambiguous_projection'` and unconfirmed `curation_overrides.source='legacy_unknown'` with revision 0 / `legacy:*` operation keys. Further repair must be based on surviving source/audit evidence, not equality with AI tags. No production history was changed in this work.
- The archive has an ON DELETE CASCADE FK. Deleting a bookmark removes its captured private values. Rollback keeps the additive table/marker/trigger; older direct-column writes remain captured. No destructive down migration or production migration was run.
