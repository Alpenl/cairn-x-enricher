此前正常分类完成时，`result.raw_judgments` 没有进入 run 表；读回只重建 answers/spec/model，缺少实际 wire state hash、逐问题 hash 和 batch identity，生产 opt-in 不能重用正常存储的记录。另有 alias 与具体 resolved model 不同导致直接失败、partial 最新记录被跳过、分批漂移答案先合并后检查等缺陷。

迁移 **0020_run_provenance.sql** 增加 `raw_judgments`、`evidence_snapshot_id`、`source_hash`。旧行保持 NULL，不从最新快照或当前问题补造历史身份。正常完成在原事务与同一 guard 中写入实际领取的 snapshot ID/hash；原始输入 snapshot 与预算后的 wire state 分别保留。run 的 `attempt` 来自权威领取次数，而非 revision。

版本 1 元数据记录实际 bounded wire state 原字节、state hash、逐问题 hash、batch semantics、本次 HTTP 调用的问题集合/request hash、requested/resolved model、usage/缺失、status/latency 和每个复用问题的来源 run ID。当前 run 只汇总新调用费用；全复用明确 0 calls / 0 tokens，来源仍可追溯，不把旧费用再次相加。失败调用轨迹从分类器返回，处理器日志保存不含原文/凭证的调用元数据；不会记录成成功 run。

Worker 验证新元数据与不可变 spec、typed answers、state/coverage、逐问题 hash、调用覆盖及 usage 相互一致；复用来源必须属于同一收藏、来自 succeeded/complete 运行，且实际模型、state、问题定义与答案相同。同来源 run 多个问题复用只读取一次。旧消费者不提供版本化元数据仍可提交，保持 unknown。

Go `StoredRun.DecodeJudgments` 是 processor、CLI、仪表盘与评估导出的共同恢复入口；检查存储的 spec/model/answers/调用/用量身份，数据库 run ID 由读取端赋予，不能由 JSON 自称。缺身份或最新 partial/failed 不认证可复用。配置 alias 时不继承旧解析结果，调用前执行一次有界完整评估；新调用后契约失败或模型漂移没有完整推断 fallback。明确固定模型可复用相同实际模型的历史，即使历史请求使用了 alias。

分批路径修复在确认具体模型相同之前插入答案的错误：第一批确立实际模型，其他版本的答案不合入，coverage 为 partial，所有已发生调用的 usage 仍保留。取消或错误返回保留已发生调用轨迹。普通检查不调用付费 API。

评估导出使用该 run 保存的 source hash/snapshot ID 和 wire 身份；最新材料变化不会改写旧样本身份。旧未知来源明确 `source_hash_unknown=true`，不能参与证明分组无泄漏；不再用 spec hash 代替 source hash。生产输出标 `machine_prediction`，没有参考标签，不伪装 synthetic/human gold。B08 live runner 在答案校验失败但 usage 可读时仍保留用量；离线 wire 恢复保留原延迟而非解码耗时。

## 真实生产验收

`tests/local-integration/run.sh` 启动真实本地 Worker、完整迁移、D1/R2；`TestLocalWorkerStoredQuestionReuse` 使用正常 Go `NewStaged → claim → bound snapshot → classifier → complete → run read`，只有付费提供者替换成本地 typed HTTP 合同服务。不是给 helper 手填一份完美历史。

| 触发 | 实际提供者调用与结果 |
|---|---|
| 首次正常分类 | 1 次 / 4 个问题；实际 wire state、hash、模型、usage、来源 snapshot 可读回 |
| 只修改 topic_llm 的定义 | 1 次 / 1 个问题；另外 3 个来自首个存储 run；本次 usage 仅 10 input tokens 的合同夹具值 |
| 显示名称变化 | spec 不变；正常重分类 0 次调用，全部来源绑定前一 run |
| 阈值变化 | 从数据库恢复 raw 后纯 Decide，0 次调用 |
| 材料 snapshot 更新 | 旧运行导出保留旧来源；下一次分类独立新输入、1 次完整调用 |
| 缺身份的旧格式 run | 1 次完整调用，不假复用 |
| 最新 partial run | 不跳过它去伪装“最新成功”；1 次完整调用 |
| alias 配置与相同 alias 再次请求 | 每轮恰好 1 次完整调用，不沿用旧 alias 解析 |
| 改回相同具体 pinned model | 相同实际输入/问题/模型可复用，0 次调用 |
| 修改一题后提供者返回另一具体模型 | 恰好 1 次 / 1 个问题；拒绝拼接，未追加成功 run，没有第二次完整调用；日志保留此次调用 |

该场景总计 **8 次本地提供者请求**，本轮 **0 次付费模型调用**。既有 lifecycle、版本竞争、display rename、source checkpoint/bound read、entity snapshot identity 5 个场景继续通过。长输入真实 HTTP 预算与旧 source/archive 回归保留。
