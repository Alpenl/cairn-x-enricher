## 修改前失败与最终行为

[API26 旧实现失败对照](logs/20260923-android-delete/android-delete-baseline.log)使用实际 ViewModel/DataStore/HTTP，在 DELETE 204 后释放已发出的详情响应，触发 `late detail must not revive a deleted link`。不是从 helper 推测的缺陷。模型、外部收藏和图片数据均为合成；该失败首先证明详情复活，不冒充全部后续缓存路径的独立旧失败。

- 发 DELETE 前把删除意图写入现有 DataStore，只存 full account/server fingerprint、数字 ID 和 confirmed 位。未确认意图阻止该账号/收藏的新整理入队和队列重发，原有动作暂保留；不把普通 503、超时、鉴权失败或坏 JSON 当成功。启动/账号激活有界续删一次，用户可明确重试，不做无限网络循环。
- 204 或精确错误 `503 deletion_cleanup_pending` 确认收藏已删除；同一 DataStore edit 删除该账号的旧整理动作并写确认位。后者 UI 明确“收藏已移除，附件正在后台清理”，不声称 R2 物理清理完成。其他 503 仍未确认。存储错误可见且不声称本地清理成功。
- 删除与正在执行的整理确认使用共享 queue mutex，避免删除动作记录后迟到 ack 破坏队列。确认状态通过持久流传递到当前账号；A→B 和 A→B→A 均不会误清别人的数据、恢复被删内容或执行旧导航 callback。
- 清除 root/library/search、detail load、edit draft、v2 selection/draft/conflict/busy/queue 的对应 ID；失效 selection request 序号。已确认 ID 拦截后续迟到详情/多维响应及 stale list/search/library 页，重建 ViewModel/进程后由日志恢复守卫。另一个账号相同数字 ID 和动作保留。不能可靠归属的旧 suffix-only 动作仍留存待明确归属，不越权删除；已删收藏 UI 不显示它们。
- 另查到 12 MiB Bitmap LRU：旧 cache key 含原 token，且不响应删除。现在只使用账号指纹/image key；确认删除清除精确账号/收藏缓存，拒绝迟到下载解码后再次写入。Composable 观察失效版本，丢弃自己 remember 的 Bitmap；其他账号/收藏不清除。设备测试把已缓存图片放进实际 ViewModel 删除场景并验证清除和迟到 put 拒绝，另测隔离边界。

实现与恢复说明在 [Share privacy-deletion.md](https://github.com/Alpenl/cairn-share/blob/c2091fac784407ad25bb47620ed72070965abb1e/docs/privacy-deletion.md)。没有承诺远程擦除导出文件、系统截图、其他应用缓存。旧 Worker 没有持久 DELETE 凭据的兼容、完整删除保留期和 NAS 图片代理兼容仍需独立核验。
