# 网页工作区

本次重构依据 `cairn-redesign/cairn-reader.html` 设计稿，覆盖 NAS 网页端。主题、间距、字号、边框与阴影集中在 `internal/dashboard/web/tokens.css`；工作区布局在 `app.css`，正文、媒体、标签身份及服务诊断的业务样式在 `features.css`。

## 页面与交互

- 宽屏采用 220px 导航、350px 列表、可伸缩正文和 316px 整理面板；1320px 以下整理面板改用抽屉，1060px 以下导航收为图标栏，760px 以下列表和阅读区逐页显示。
- 标签库、合集、AI 整理和设置使用独立页面。标签库和合集保留未保存的编辑草稿，切页时暂停隐藏正文的预取、身份轮询和整理面板读取。
- 整理面板分为整理、处理和记录。运行历史按需分页加载；打开原帖、净读版、原文、图片、视频和独立相关链接沿用现有读取链路。
- `Ctrl/⌘ K` 打开命令搜索，`I` 切换整理面板。原有 J/K、状态键、多选、撤销、导出及可分享 URL 保留。
- 合集和标签操作继续使用原接口的操作身份、版本校验及审计记录。页面不内置示例收藏，不自动重新分类或启动模型任务。

## 组件与构建

通用表单、按钮、选择器、复选框、菜单、弹窗、抽屉和选项卡复用 **Web Awesome 3.14.0**。选用组件由 esbuild 打包到本地，系统图标和 MIT 许可证随应用发布；运行时不访问外部 CDN、字体或图标服务，保持现有 CSP。

列表行和主搜索框使用轻量原生 DOM，避免为每一条收藏创建组件实例，也保留中文输入法的原生行为。`controls.js` 统一适配管理表单的值、标签和事件。

```sh
npm ci
npm run build-components
npm run check-components
make verify
CHROME_PATH=/usr/bin/google-chrome npm run test-browser
```

组件源码位于 `internal/dashboard/components/`，生成资源提交到仓库。应用样式与组件主题一并打包，页面仅加载一份 CSS，避免运行时逐层加载样式。修改样式或升级依赖后都须重新执行 `npm run build-components`。Go 和 Docker 构建直接嵌入已核验资源，生产不需要 Node。组件输出校验纳入浏览器 CI，升级依赖后应检查许可证并运行全部回归。

## 搜索与渲染性能

主搜索沿用 180ms 输入防抖、输入法合并、旧请求取消、本地首批预览和服务端全文补齐。预览不能替代服务端的最终搜索结果。查询缓存继续受 TTL、条数、字节与版本失效限制；完整摘要快照仅在满足现有合同和范围时回答本地筛选。

列表按收藏身份复用未变化的行、缩略图和焦点，只调整发生变化的节点。脱离页面的行缓存最多保留 240 条；正文、媒体和 Blob URL 继续使用原有独立缓存边界。离屏条目使用 `content-visibility`，追加分页使用文档片段。标签库搜索复用管理行组件。

筛选面板锚点与计数槽保留稳定尺寸，点击换行标签时不重建筛选节点、不改变字体粗细或弹层位置。管理页与正文相互独立，搜索不重绘整套工作区。

## 验收

`management-ui.mjs` 覆盖 320/390/900/1100/1600px、浅色/深色、管理表单、抽屉和命令搜索；`stable-facets-browser-test.mjs` 逐帧验证换行标签无位移或节点移除。搜索、筛选、身份失效、离线缓存、富文本和媒体由现有浏览器套件验证。

`tests/local-integration/browser-e2e.sh` 使用固定版本的真实 Worker、隔离 D1/R2 和本地模型替身，覆盖人工标签、管理目录、合集、冲突、响应丢失重试和自动整理审核。所有验证都不使用付费模型或生产写入。

可用 `CHROME_PATH=/usr/bin/google-chrome node tests/browser/redesign-evidence.mjs` 重新生成合成数据页面截图，默认写入 `/tmp/cairn-redesign-evidence/`。合成截图仅用于开发验收，不代表生产内容或生产耗时。
