# 标签粒度与导航

2026-10-02 的产品修订，替代 [原标签方案](tag-system-design.md) 中只在默认界面使用宽主题的决定。本文描述实现合同；实际发布身份以 [部署合同](deployment.md) 和 stack manifest 为准。

## 内容重点与稳定导航

主题仍使用同一规范目录和 `system/topics/<id>` 身份。宽主题与具体主题都有自动建议、逐标签人工决定和当前有效归属；不新增一个必须由用户维护的个人标签层。

例如一篇写真生成 Skill 可显示“写真 · 图像生成 · Skill”。写真描述内容目标，图像生成描述工作领域，Skill 描述资源类型。卡片优先展示具体主题，显示数量不改变完整归属。置信证据不足时允许少于两个自动标签；人工添加的第六个及以后标签不会被自动策略删除。

一个概念是否成立取决于含义清楚、能否复用和检索价值，不设“必须出现三次”的门槛。低频概念可以成为有效标签，但不自动占据侧栏首页。禁止把“AI写真Skill”等已有概念组合反复建成新身份，也不能将“写真”“人像生成”误合并为同义词。

写真也可以涉及实拍，所以不建立“写真一定属于图像生成”的继承规则。相关关系用于候选寻找和导航提示，不自动添加、接受或排除任何标签；筛选始终匹配有效标签的精确身份。

## 目录与客户端协议

新版目录 `2026-10-02.1` 保留原有十三个活跃主题，并加入二十四个具体主题。历史 `.2`、`.1` 和 legacy 目录保持原定义，用于解释和重放历史运行。

| 字段 | 含义 |
| --- | --- |
| `granularity` | `broad` 或 `specific`；历史省略按 `broad` 展示 |
| `navigation` | 是否进入默认稳定导航；不改变标签是否有效或可搜索 |
| `recall_terms` | 候选召回线索；不是同义词，不可据此合并标签身份 |
| `aliases` | 确认的同义名称或拼写变体，添加标签时复用规范身份 |
| `relations` | 显式相关或其他已定义关系，不隐式继承归属 |

现代调用同时请求 `X-Cairn-Tag-System: 1` 和 `X-Cairn-Topic-Granularity: 1`，服务端明确确认能力。未协商的新字段会从旧响应中剥离，不能用未知字段破坏旧严格客户端。界面只需要粒度和导航元信息，召回线索不进入普通产品操作。

第一批具体概念为：写真、人物一致性、白板动画、代码重构、文风模仿、去AI味、小说创作、微信记录、公众号运营、Agent记忆、长期指令、界面动效、设计规范、网页采集、B-roll、录屏、本地推理、模型微调、模型量化、浏览器自动化、行情数据、英语学习、逆向分析、页脚设计。具体定义、正反例和召回线索以 Worker 目录为权威；不将私人收藏正文复制进公共词表。

## 页面与筛选

网页和 Android 使用相同规则：默认导航显示宽主题及用户固定的入口；当前结果中的具体主题用于继续细分；查找全部主题可搜索名称和真别名。固定入口是按账号隔离的本地展示偏好，不创建个人标签、不修改收藏、不构成人工分类确认。

新增 `topic_refinements` 是需要全部满足的具体主题集合，与原 `topics` 条件相交。例如：

```text
topics=ai_coding,agent_workflow&topics_mode=any&topic_refinements=agent_instructions
```

表示 `(AI编程 OR Agent配置与自动化) AND 长期指令`。点击进一步筛选不会将原有“任一”偷偷变成“全部”。细分条件有独立的活动标签，移除后恢复原查询；URL、前进后退、列表、计数、分页游标、缓存及 Android 查询身份均保留该条件。未确认新能力的服务不得声称已执行细分。

计数来自服务端当前完整结果，不根据当前加载页猜测，也不靠父子关系推算。标签点击用于筛选，移除按钮用于修改归属；两种动作独立。

## Jev 判断与自动数量策略

Jev 对独立标签分别判断。当前小目录完整覆盖五十五道问题，并在来源、模型、每题 hash 和批次语义一致时复用历史答案，只为新增问题补判。不能把复用当作任何旧答案都可移植的许可。

大目录可使用受控候选模式。召回基于实际内容、规范线索和相关概念；运行记录保存候选清单及选择身份，明确区分“未召回、未判断”与“模型判断不适用”。缺少被选中问题的答案仍是部分完成，不能伪造零概率来补齐。评价同时检查候选召回覆盖和判断结果。

v5 保持自动采用阈值，不把概率增加任意奖励。自动结果超过五个时，在已满足阈值的标签中为最高概率的具体主题、宽主题和资源类型各保留至多一位，其余按原概率与稳定身份选择。人工决定始终在自动策略之后解析，不因数量目标被裁剪或重新加回。

## 新概念治理

新概念先成为提案，不能直接写入正式词表。主题提案必须包含规范名称、语义定义、正反例、粒度、相关关系，以及至少一处真实存档原文的逐字证据和内容 revision。

校验拒绝已有名称或别名冲突、可由已有主题与资源组合表达的名称、失效来源、非原文证据和未经定义的关系。一条有依据的低频概念可以提交，不要求多篇出现。提案、批准与发布分开：批准不等于给任何收藏添加标签，语义变化必须随新的不可变词表版本发布。历史草案保留，未经新合同校验的主题草案不能直接升级为正式定义。

这一步是规范目录维护，不要求用户逐篇维护自定义标签。尚未纳入目录的内容仍能通过原文搜索找到，不能宣称词表覆盖所有未来概念。

## 升级与验收

- 更新前备份，保留原文、人工覆盖、自定义归属、所有旧 run 和预算账本。新目标以 generation 和不可变 spec/policy 身份切换，不覆盖历史。
- 只对有原文的收藏执行授权补判；缺文项目保留明确状态。临时补判额度有界，结束后恢复日常限制，不清账。
- 对“写真”可找回用户指出的收藏建立明确正向约束；其他助手整理的参考答案保持 `automatic_reference`，不冒充人工金标准。
- 用真实服务验证宽主题与具体主题组合、多个宽主题任一后继续细分、标签计数、分页和修改后的失效。两端检查标签点击、常用入口、账号隔离、离线与旧能力兼容。
- 上线前固定跨仓提交并通过现有完整门禁，比较冷查询与缓存切换，确保新增粒度不会恢复逐标签串行等待。
