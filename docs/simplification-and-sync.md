# 项目简化、性能消融与 Cairn Share 同步

日期：2026-09-12。范围覆盖 Go 富化与调度、网页列表/阅读/导出、Cloudflare Worker/D1/R2、
Android 输入/存储/网络/列表/阅读/整理。所有删除实验在临时副本内运行；基线包含任务开始时
两个仓库已有的未提交改动。此前的真实模型质量实验另见 [ablation.md](ablation.md)，本轮
不重新调用付费模型，也不修改生产数据库。

## 已删除的设计及理由

| 设计 | 当前实现 | 删除依据 |
| --- | --- | --- |
| Eino 两节点工作流及其传递依赖 | 生成 → 校验 → 分类归一化，普通 Go 调用 | 固定顺序没有运行时分支；全部行为回归通过，固定输入基准显著减少分配与包体 |
| 框架错误包装及统一解包 | 原样传播生成器错误 | 消除框架前缀，并保留 `errors.As` 所需类型和调用上下文 |
| 配置解析后的重复数值/时长校验 | 只在解析入口检查边界 | 全仓调用分析和边界回归确认没有第二个配置构造入口；有效范围仍有消融测试 |
| Android `LinkRepository` 纯转发类 | ViewModel 直接使用 `LinksApiClient` | 没有缓存、事务、切换数据源等独立责任 |
| Android 全量列表聚合接口及结果包装 | 逐页读取摘要，每页到达即可显示 | 首页无需等待全部收藏；详情单独读取全文 |

保留 Responses 协议适配、严格 JSON Schema、X 搜索证据、中文标题校验、词表归一化、
受控图片归档、重试退避、原文恢复、并发上限、租约和关停排空。它们有独立的业务或可靠性
责任，逐项删除会造成契约、内容或任务生命周期回归。没有因为测试未检出某个变体就删除功能。

## 可复查的性能结果

| 指标 | 基线 | 当前 | 变化 |
| --- | ---: | ---: | ---: |
| 工作流固定输入耗时，中位数 | 9,079 ns/op | 1,045 ns/op | 减少 88.5% |
| 工作流内存分配 | 12,699 B/op | 659 B/op | 减少 94.8% |
| 工作流分配次数 | 135 次/op | 11 次/op | 减少 91.9% |
| Go 模块数，排除主模块 | 83 | 8 | 减少 75 个 |
| 同参数构建的 Linux amd64 二进制 | 20,181,257 B | 9,851,145 B | 减少 51.2% |
| 40 条收藏列表的未压缩响应 | 4,708,973 B | 33,053 B | 减少 99.3% |
| 阅读页初始 DOM 节点 | 574 | 334 | 减少 41.8% |
| 折叠原文的初始段落数 | 240 | 0 | 展开后才创建 |
| 未变化的轮询是否保留正文/图片节点 | 否 | 是 | 保留阅读选区与图片节点 |

工作流数据使用固定生成器，衡量编排成本，不是模型推理时间。浏览器数据使用真实前端和
合成收藏，衡量响应体与 DOM；没有宣称生产首屏或公网流量按同比例加速。390×844 视口
两侧均无横向溢出；新版原文展开后仍完整显示 240 段。
原始数据和复现步骤见 [experiments/performance](../experiments/performance/README.md)。

网页实现还包括：检索结果批量插入 DocumentFragment；按 URL 建立标签更新索引；
未变化的首页响应跳过重建；用户翻页后不再被定时首页请求覆盖。搜索仍获取全文以保留
命中摘要。Markdown 导出遇到摘要行时按需读取详情，任何读取失败都会终止导出，避免生成
缺少正文却看似成功的文件。

Android 对库统计和筛选使用有明确输入的 `remember`；最早待学习项使用线性扫描，排序时
复用已解析日期；阅读正文按段落使用 LazyColumn，图片在可见时加载、解码边长不超过
2048 像素，并使用 12 MiB 有界缓存。缓存包含服务器、凭据和对象键。刷新摘要只有在 URL、
备注、状态和内容版本都一致时才复用已加载正文，防止链接编辑后显示旧正文。分页期间的
本地编辑/删除也会保留。

## 消融方法与结果

Go 的 [16 项架构消融原始结果](../experiments/architecture/results-20260912.json) 全部由
行为断言检出。覆盖搜索证据、标题、strict schema、分类、错误上下文、HTTP 重试、原文恢复、
图片保留、定时/人工关停排空、队列容量、鉴权、就绪状态、并发边界、原文延迟创建和完整导出。
实验入口为 `make ablation-architecture`。

Cairn Share 的 `ablation/run.py` 共覆盖 71 个变体：Worker 39 项，Android 32 项。
每个变体先校验精确修改位置，再复制当前工作区、只移除一项能力并运行对应验证。
Worker 最终结果为 29 项行为检出、8 项编译/结构检出、2 项未检出，无超时；完整表在
伴随仓库的 `ablation/WORKER-20260912.md`。SQL 通配符和无可信长度头的图片流限制
最初未被检出，补上实际边界场景后可由断言检出。

Android 单元/构建矩阵的原始结果位于伴随仓库 `ablation/ANDROID-STATIC-20260912.md`：
13 项行为检出、1 项构建检出、18 项未检出。逐页显示和图片加载还使用真实设备测试进行针对性消融。
设备实验必须先让对应未修改代码
通过相同测试，否则记为基线失败并跳过，不会伪造行为检出。

两项最终设备消融均由界面断言检出；合并结果见伴随仓库 `ablation/ANDROID-20260912.md`：
13 项 JVM 行为检出、2 项设备行为检出、1 项构建检出、16 项未检出。首次分页设备基线因
模拟响应 8 秒后自动放行而产生时序失败，该记录仍单独归档；最终测试由断言完成后才放行
第二页响应。全仓 87 个单项变体合计 60 项行为检出、9 项编译/结构检出、18 项未检出。

完整未修改 App 在 API 26 软件模拟器上的 9 项设备回归通过，Android 31 项单元测试、lint、
APK 构建和 instrumentation 编译通过；Go `make verify` 通过，包括 56 项前端检查；
Worker 最终 50 项测试、TypeScript 类型检查和 Wrangler dry-run 通过。Worker 消融矩阵使用
49 项测试基线，其后补充的第 50 项专门验证增强详情在“学习标记/URL 修改”后的响应契约。

Worker 仍未被现有断言检出的两项是尾斜杠路由规范化与调试台按钮；它们有可观察的用户行为，
本次保留。Android 的 UI、下载/安装与偏好等未检出项也在报告中明确列出，不能据此认为多余。
这里的消融是有边界的行为变异验证，不是覆盖所有可能组合的形式化证明。

## 数据库和 App 的共同契约

| 消费端/操作 | 接口 | 数据形态 |
| --- | --- | --- |
| 旧 App | `/api/links` 及单条详情 | 原来的六字段，继续兼容 |
| 新 App 列表 | `/api/links?include=enrichment` | 摘要、标题、分类、状态，`content_loaded=false` |
| 新 App 详情 | `/api/links/:id?include=enrichment` | 完整双语正文、图片键、相关链接，`content_loaded=true` |
| 新 App 词表/图片 | `/api/taxonomy`、`/api/images/:key` | 使用 App Token |
| 新 App 人工整理 | `PATCH /api/links/:id/curation` | 收藏原因、整理状态、分类选择或 `classification:null` |
| 网页普通列表 | Go 代理到 `/api/enrichment/jobs?view=summary` | 轻量列表；详情和全文搜索保留完整内容 |
| 模型任务 | `/api/enrichment/*` | 独立 Enricher Token、任务租约、重试和写回 |

App 能显示 AI 标题、摘要、原文/译文、R2 归档图片、相关链接、分类及收藏原因；可以按主题、
形态、用途、来源、整理状态、待确认和时间筛选，并保存人工整理或恢复自动分类。全文搜索
在数据库中执行，结果仍只传摘要。没有复制一套词表或新增客户端数据库。

迁移 `0007_add_bookmark_curation.sql` 提供分类及人工整理字段，新增
`0008_invalidate_enriched_link_cache.sql` 在相关更新的同一事务内递增已有 `links_generation`。
Worker 缓存键同时区分增强/旧协议及所有筛选条件。模型完成和人工整理后，App 的已缓存
列表与详情立即失效；列表查询不从 D1 读取两个大正文字段。

真实 D1/R2 测试运行在 Cloudflare 本地测试环境。另在内存 SQLite 中按 0001–0007 建库、
插入双语正文和人工整理，再应用 0008，确认原行逐字段保留且之后更新递增缓存版本。
最终发布顺序为：迁移 D1 → 部署 Worker → 升级 Enricher → 安装新 App。

本轮只完成本地代码、迁移文件、构建和验证；生产 Worker/D1 尚未发布或迁移。
旧 Worker 仍可为新版 App 提供基础链接，完整阅读与整理功能需要先部署配套 Worker。
